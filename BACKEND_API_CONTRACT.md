# GrowthOS Backend API Contract & Specification

This document is the authoritative API contract generated by reverse-engineering the GrowthOS backend repository codebase (`Growth-OS-Backend`). It contains every currently implemented backend route under the `/api` prefix, exact request/response definitions, authentication requirements, Meta Graph API interaction specifications, and contract analysis against the GrowthOS frontend application.

---

## Centralized Architecture & Infrastructure Notes

- **Server Prefix:** `/api` (configured in `server.js`).
- **Authentication Middleware (`middleware/authMiddleware.js`):**
  - Header Required: `Authorization: Bearer <JWT_TOKEN>`
  - Decoding Logic: Verifies token with `process.env.JWT_SECRET || 'secret'`. Decodes `user.id` or `id`, queries `User.findById(id).select('-password')`, and attaches to `req.user`.
  - Failure Responses:
    - Missing Header: HTTP `401 Unauthorized` (`{ "message": "Not authorized, no token" }`).
    - Invalid/Expired Token: HTTP `401 Unauthorized` (`{ "message": "Not authorized, token failed" }`).
- **Global Error Handler (`middleware/errorMiddleware.js`):**
  - Response JSON: `{ "message": "<Error Message>", "stack": "<Stack Trace in Dev / null in Prod>" }`.
  - Default Status: HTTP `500 Internal Server Error` if status code is `200` when error is thrown.
- **Global Rate Limiting (`server.js`):**
  - Applies to `/api/*`: 100 requests per 15-minute window per IP. Exceeding returns HTTP `429 Too Many Requests`.

### 13. GET /api/meta/callback
- **HTTP Method:** `GET`
- **Route Path:** `/api/meta/callback`
- **Authentication Requirement:** Public (Meta Browser OAuth Redirect)
- **Required Headers:** None
- **Request Params:** None
- **Request Query Parameters:**
  - `code` (String, required): Authorization code returned by Meta.
  - `state` (String, required): Cryptographic state parameter.
  - `error` (String, optional): Error code if Meta auth failed.
  - `error_description` (String, optional): Error description from Meta.
- **Request Body:** None
- **Controller Handling Request:** `metaController.callback` (`controllers/metaController.js`)
- **Service/Function Called:** `MetaOAuthState.findOneAndDelete`, `metaService.exchangeCodeForToken`, `metaService.getMetaUserProfile`, `metaService.getGrantedPermissions`, `MetaIntegration.findOneAndUpdate`
- **Meta Graph API Called Internally:**
  1. `GET /v26.0/oauth/access_token` (Short-lived token exchange)
  2. `GET /v26.0/oauth/access_token?grant_type=fb_exchange_token` (Long-lived User Access Token exchange, ~60 days)
  3. `GET /v26.0/me?access_token=...` (Fetch Meta User Profile)
  4. `GET /v26.0/me/permissions?access_token=...` (Fetch Granted Scopes)
- **Required Meta Permission:** None for callback execution.
- **Access Token Type:** User Access Token (Long-lived ~60 days).
- **Success Response Structure:**
  - **If `FRONTEND_URL` is set:** `HTTP 302 Found` (Redirects to `${FRONTEND_URL}?meta_status=success`)
  - **Otherwise:** `HTTP 200 OK`:
    ```json
    {
      "success": true,
      "message": "Meta account successfully connected",
      "metaUserId": "10229876543210987"
    }
    ```
- **Error Responses:**
  - `HTTP 400 Bad Request`: `{ "message": "Meta authorization failed: <error_description>" }`
  - `HTTP 400 Bad Request`: `{ "message": "Missing code or state parameter in Meta callback" }`
  - `HTTP 400 Bad Request`: `{ "message": "Invalid or already consumed OAuth state token" }`
  - `HTTP 400 Bad Request`: `{ "message": "OAuth state token has expired. Please initiate connection again" }`
- **Frontend Consumption Status:** Not yet consumed by frontend.

### 3. Contract & Schema Mismatches Between Frontend & Backend

1. **User Object Key in Auth Responses:**
   - Frontend `AuthPage` expects `data.token` and `data.user.onboardingComplete`.
   - Backend `POST /api/auth/login` and `POST /api/auth/register` return `token` and `user` object with `onboardingStep` and `onboardingComplete`. **Matches.**
2. **Onboarding Update Field Structure:**
   - Frontend `OnboardingWizard` sends `PUT /api/users/onboarding` with body `{ onboardingStep, onboardingComplete, businessType, companyName, industry, companySize, b2bClients, companyWebsite, position, phoneNumber, brandColor, pricingTier }`.
   - Backend `userController.updateOnboardingStep` explicitly defines `allowedFields` matching all of these keys exactly. **Matches.**
3. **Dashboard Mock Data Shape vs Backend GROmentum Delivery Envelopes:**
   - **Lead Source Breakdown:** Frontend `LeadSourceCard` expects an array `[{ name, percentage, color, icon }]`. Backend `GET /api/meta/insights/overview` returns `adsOverview` (spend, impressions, reach) and `socialOverview`. Frontend must transform backend metrics into percentage shares.
   - **Campaign Cards:** Frontend `CampaignCards` expects `[{ id, name, client, tags, icon, iconBg }]`. Backend `GET /api/meta/insights/campaigns` returns `[{ campaignId, name, status, effectiveStatus, objective, budget: { dailyBudgetFormatted } }]`. Frontend must map backend `campaignId` to `id` and format tags/status.
4. **Currency Subunit Formatting:**
   - Frontend components display monetary values as formatted strings (e.g. `"$50.00"`). Backend Phase 3 `GET /api/meta/insights/campaigns` provides `dailyBudgetFormatted` calculated with `getCurrencyDivisor`, allowing direct string formatting on the client without manual subunit division.
